## 판정

실행·기본 문서 열기는 성공. 원본 페이지 재현성은 불합격.
Windows 실제 GUI 화면을 관찰하고 sample/corpus의 PDF를 Poppler로 렌더링해 비교했다.
모든 페이지에 대한 전수 검사는 아니며, 글꼴 대체와 DPI 조건별 비교는 미실시.
앱 스크린샷은 이번 대화의 도구 출력으로 확인했고 별도 이미지 파일로 저장하지 않았다.

## 재현된 문제

### P1: 페이지 분할·문단 위치 계산
- 윤리기준: PDF 표지 한 장에 있는 제목·날짜·기관 로고가 GUI에서는 나뉘어 표시된다.
  GUI 1쪽에는 제목만 있고 3쪽에는 날짜·로고와 다음 목차 제목이 함께 보인다.
- 식약처: PDF 첫 페이지 안의 본문·설명이 GUI 1~3쪽으로 분리된다.
  2쪽은 상단에 큰 공백이 있고 하단에 설명 두 줄만 있다.
- 검토 후보: src/gui_win.c measure_para_height의 lineseg vertpos 처리,
  draw_para의 좌표 기준, rebuild_pages의 블록 단위 높이 누적.
  원인 확정 전 원본 XML lineseg의 좌표 의미를 확인해야 한다.

### P1: 표 내부 텍스트 폭·배치
- 규제합리화 첫 페이지의 큰 제목과 하위 문장이 우측 셀 경계·용지 밖으로 넘어가 잘린다.
- 원본 PDF의 작은 상단 표가 GUI에서는 과도하게 높고, 내부 항목 간격·순서가 다르다.
- 검토 후보: draw_table의 셀 클리핑, 중첩 콘텐츠 순서, lineseg 폭과 셀 너비의 관계.

### P2: 정렬·외관 차이
- 윤리기준 표지 제목이 원본의 굵은 가운데 정렬과 다르며, 원본에 없는 셀 경계가 보인다.
- 기관 로고가 가로·세로 비율이 다르게 보이고 기관명 배치도 다르다.
- 검토 후보: 폰트 대체/굵기, GDI 글꼴 DPI와 고정 페이지 좌표의 일관성,
  이미지 종횡비, 테두리 없음 처리.

### P2: 키보드 페이지 이동 중복 가능성
- 윤리기준 메인 창에서 PageDown 1회 후 1쪽에서 3쪽으로 이동했다.
- 식약처에서 다음 버튼 1회는 1→2쪽, 버튼 포커스에서 PageDown은 2→3쪽이었다.
- 메시지 루프가 WM_KEYDOWN을 SendMessage로 전달한 뒤 DispatchMessage도 수행한다.
  메인 창/자식 버튼 포커스에 따른 중복 처리 여부를 재현 테스트할 필요가 있다.

## 통과한 항목
- ZIP 추출본 실행과 버전 0.3.1 표시.
- 자동 샘플 열기, Ctrl+O로 한글 경로 HWPX 두 종 열기.
- 세 문서의 한글·표·기관 로고가 실제로 표시됨.
- 다음 버튼으로 페이지 이동.
- 관찰 중 크래시나 문서 열기 오류 없음.

## 권장 수정 순서와 재검증 기준
1. lineseg 좌표 정규화와 페이지 높이 계산: 과도한 공백·페이지 증가부터 수정.
2. 셀 너비/텍스트 클리핑과 중첩 콘텐츠 배치 수정.
3. 폰트·정렬·로고 비율·테두리 개선.
4. 메인/버튼 포커스별 키보드 페이지 이동 확인.
5. 같은 바이너리에서 CTest 재실행 후 동일 GUI 절차를 재검증.

페이지 수만 맞추는 것으로 통과 처리하지 않는다. 제목·본문·표·그림의 페이지 소속,
줄바꿈, 용지 밖 잘림을 함께 확인한다. 최종 단계에서 전체 페이지와 창 크기/DPI 조건을 확대한다.

이번 작업은 검증과 보고서 작성이며 제품 소스·배포 EXE는 변경하지 않았다.
