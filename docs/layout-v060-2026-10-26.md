# 0.6.0 페이지 수 차이 원인 분석 및 개선

검증일: 2026-10-26. Windows / MSYS2 UCRT64 GCC / Release / 96dpi 페이지 비트맵.

원본은 sample/corpus/의 같은 이름 PDF다. 페이지 수를 강제로 고정하거나 본문을 생략하여 맞추지 않았다.
실제 측정·흐름·셀 배치를 수정한 결과이며, 본문 소스 오프셋의 연속성과 기존 7개 golden 문서의
모든 비공백 run 텍스트가 그대로임을 별도로 확인했다. 본문 텍스트 보존은 모든 글자가 원본과 같은 모양으로 보인다는 뜻은 아니다.

## 1. 처음 어긋난 위치 분석

규제합리화 1쪽의 표·그림 앵커 공백이 별도 문단 높이로 다시 더해져 마지막 본문 일부가 2쪽으로 밀렸다.
이어서 저장된 좌표의 초기화를 또 페이지 넘김으로 처리해 본문이 조금만 있는 페이지가 발생했다.
셀 안 인용문 앞의 ‘현장 목소리’ 표도 본문 첫 줄에 붙는 요소인데 별도 높이로 더하고 있었다.

마지막 연락처 표에서는 마지막 줄의 간격을 셀 바닥 여백처럼 더했고, 표 뒤 고정 8픽셀 때문에
마지막 조각만 별도 페이지에 남았다. 고정 여백을 없애고 실제 글자 잉크 높이를 하한으로 유지했다.

## 2. 문단 측정과 저장된 조판 해석

윤리기준의 5쪽에서 간격이 누적되는 원인은 문단 속성의 switch/case 선택이었다.
지원 가능한 2016 HwpUnitChar 분기에는 문단 앞 간격 1500이 있는데, 기존 코드는 호환용 default의 3000을 선택했다.
인식한 namespace의 분기를 우선 읽도록 수정했다. 예시의 실제 원본 XML과 PDF 줄 위치를 대조했다.
인식하지 못하는 대체 분기는 기존 fallback을 유지한다.

실제 빈 문단의 줄 정보와 글자 스타일을 보존하고, 개체만을 위한 공백 앵커는 IR에 유지하되 높이에 중복 반영하지 않는다.
개체 뒤 실제 텍스트는 공백과 구분한다. 장평·자간의 소수 픽셀은 누적한 뒤 화면 좌표로 반올림한다.
폰트 크기는 원본 HWPUNIT에서 픽셀로 직접 변환한다.

## 3. 병합 셀·중첩 표의 흐름

중첩 표의 원본 문단 인덱스를 보존하여 본문 뒤로 일괄 이동하던 순서를 고쳤다.
앞부분에 단일 인라인 표가 있는 문단은 해당 폭을 첫 줄에서 확보하고, 저장된 줄 textpos에서 그 제어 영역을 보정한다.
여러 개체가 섞인 복잡한 인라인 구성은 무리하게 같은 규칙을 적용하지 않고 별도 흐름 배치로 남긴다.

세로 병합 셀을 포함하는 긴 표는 행 그룹 전체를 보존하느라 페이지가 비지 않도록 모든 셀의 공통 잉크 영역 밖에서 분할한다.
반복 머리행은 본문 공간에서 높이를 차감하며 원본 본문 오프셋을 소비하지 않는다.
윤리기준의 마지막 긴 표는 기존 6쪽에서 4쪽으로 줄었고, 반복 머리행도 유지된다.

## 4. 검증과 재현

- CTest 16/16 통과. 저장 원본 보존·XML·페이지 흐름·실제 GDI·golden 회귀 검사 포함.
- 4종 문서 전체 페이지를 offscreen GDI로 렌더링하여 17/20/4/2쪽, 강제 글자 분할 및 머리행 억제 0건 확인.
- 선택 13장: 윤리기준 1/5/6/14/17, 규제합리화 1/4/18/20, 식약처 1/4, 합성 문서 1/2.
- 선택 PNG를 검토하고 다시 렌더링한 픽셀 비교 0건 차이 확인.
- 실제 0.6.0 GUI의 17쪽 표시와 5쪽 본문·6쪽 병합 표/흐름도 배치를 확인.
- GCC -Wall -Wextra -Wpedantic 구문 검사 통과.
- 기존 golden 텍스트 본문은 변경 없음. 문단 여백·빈 문단 줄/글자 스타일·인라인 줄 textpos·새 메타데이터는 의도적으로 갱신.

```powershell
# 일반 C 테스트
.\scripts\build-windows.ps1 -Action Test
# Python + Pillow가 있는 실행 파일 지정
.\scripts\build-windows.ps1 -Action VisualTest -PythonExe python
# 특정 문서의 특정 페이지 렌더링 (출력 폴더를 먼저 생성)
.\build\windows-release\layout_render.exe sample/corpus/ethics.hwpx build/render 5 6
# 기준 이미지 변경은 출력 이미지 검토 후 명시적으로만 실행
python -X utf8 scripts/visual-regression.py --update
```

layout_render는 GUI의 paint_document_page를 공유하며 BMP와 전체 조각의 layout.json을 출력한다.
이미지 검사는 tests/visual/windows의 자체 렌더 기준과 비교한다. 원본 PDF와 픽셀이 같다는 검사가 아니다.
Windows/설치 글꼴이 바뀌면 픽셀도 달라질 수 있으므로 결과를 확인한 후 기준을 갱신해야 한다.
이 도구는 개발 빌드에 포함되며 일반 배포 ZIP의 실행 파일 구성은 CLI와 GUI다.

## 남은 차이와 후속 작업

페이지 수가 같아도 원본과 완전 일치하지 않는다. 실제 비교에서 다음 차이가 남아 있다.

- 한컴 전용 글꼴/사설 영역 문자와 일부 기호가 대체 글꼴에서 네모로 보일 수 있다.
- 언어별 글꼴·상대 글자 크기·위아래 오프셋, 탭 리더와 정교한 양쪽 정렬은 충분히 재현하지 못한다.
- 규제합리화의 날짜 칸 등 일부 짧은 셀은 대체 글꼴 폭 때문에 원본과 줄바꿈이 다르다.
- 머리말/꼬리말 영역 및 부동 개체 위치, 투명 그림 배경·세부 테두리 차이가 남아 있다.
- 중첩 표 자체의 반복 머리행과 머리행/본문 경계를 가로지르는 병합의 머리행 반복은 아직 지원하지 않는다.
- 페이지보다 큰 그림처럼 공통 안전 절단점이 없는 개체는 연속 클리핑으로 표시하는 기존 fallback을 유지한다.

다음 개선은 페이지 수를 더 조정하는 것보다 글꼴/기호 대체, 상대 글자 크기, 탭·정렬, 머리말/꼬리말 위치 순서로 원본의 시각 차이를 줄이는 것이 적절하다.
