# 0.5.0 반복 머리행·병합 셀 분할 검증

검증일: 2026-10-26. Windows / MSYS2 UCRT64 / Release 빌드.

## 변경

HWPX 표의 repeatHeader와 셀의 header 속성을 보존하여 상단의 연속된 제목 행을 반복한다.
repeatHeader만 있고 제목 셀이 없는 표의 첫 행을 임의로 반복하지 않는다.
이는 [한컴 표 속성 도움말](https://help.hancom.com/hoffice100/en-US/Hwp/table/tableattribute/table(table).htm)의 제목 셀 설정 조건을 참고했다.
여러 행에 걸친 제목 병합은 전체 제목 영역을 포함한다. 머리행과 본문을 가로지르는 병합은
본문 중복을 피하기 위해 반복을 생략한다.

반복 머리행 높이를 다음 페이지/단의 본문 용량에서 차감한다. 반복 영역은 원본 소스 오프셋을
소비하지 않는다. 페이지 조각의 본문 오프셋은 처음부터 끝까지 연속 유지한다.
각 셀과 중첩 표의 실제 글자/개체 영역을 수집하고 공통으로 비어 있는 위치를 찾아 분할한다.
줄 간격 전체를 글자로 취급하지 않으며, 분할된 셀은 경계에서 수평 테두리를 마감한다.
병합 셀의 추가 높이는 포함된 행에 분배한다.

## 검증 결과

- CTest 16/16 통과. 순수 분할 규칙, HWPX 속성 읽기, 실제 GDI 측정·그리기, golden IR 회귀 포함.
- 첫 머리행과 다음 페이지 반복 머리행의 GDI 픽셀 비교 통과.
- 다중 머리행, 가로/세로 병합, 엇갈린 줄 위치, 중첩 표, 너무 큰 머리행·개체 검사 통과.
- GCC -Wall -Wextra -Wpedantic 구문 검사 통과.
- 기존 golden 6종은 새 표/셀 메타데이터 줄을 제외하면 기존 내용과 동일함을 비교 확인.

## 남은 제한

- 중첩 표의 내용은 분할 위치 계산에 포함되지만 중첩 표 자체의 머리행은 별도로 반복하지 않는다.
- 머리행/본문 경계를 가로지르는 병합에서는 반복을 생략한다.
- 머리행이 너무 크면 반복을 생략하거나 해당 페이지에서 억제해 본문이 진행되도록 한다.
- 페이지보다 큰 그림 등 공통 빈 분할 위치가 없는 개체는 연속 클리핑으로 표시하므로 개체가 페이지 경계에서 잘릴 수 있다.
- 원본 PDF 페이지 수 17/20/4에 대한 기존 샘플의 20/29/4 차이는 남아 있다.
- 원본 보존 저장 경로는 변경하지 않았다.
