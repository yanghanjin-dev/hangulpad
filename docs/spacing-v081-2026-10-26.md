# 0.8.1 글자 간격과 원본 행 배치

## 수정

- HWPX `useFontSpace`를 읽고 기본 공백을 반각(0.5 em)으로 계산한다. 명시적으로 글꼴 공백을 사용하는 경우 물리 글꼴의 공백 폭을 유지한다.
- 자간 백분율을 글자 크기 전체가 아닌 해당 글자의 폭에 적용한다. 좁은 괄호·쉼표·영문·공백이 음수 자간에서 과도하게 압축되던 문제를 줄인다.
- 실제 굵은 글꼴과 GDI 합성 굵기를 구분한다. 합성 굵기의 이동 폭은 보통 굵기의 105%로 계산하고, 물리 굵은 글꼴은 자체 측정값을 사용한다. 글꼴 테이블 확인과 보통 굵기 측정 글꼴은 캐시한다.
- 음수 intent의 둘째 줄 이후 내어쓰기, 양수 intent의 첫 줄 들여쓰기를 반영한다. 저장 행과 새 문단의 재배치가 같은 규칙을 쓴다.
- 양쪽 정렬은 문장 내부의 공백과 한글 문자 경계에 남은 폭을 분배한다. 마지막 줄과 강제 줄바꿈 줄을 임의로 늘리지 않는다.
- 저장된 줄이 원래 폭의 영역에 표시되는 경우 GDI와 원본 글꼴 측정 차이를 행 안의 자간으로 보정하여 원래 줄바꿈을 유지한다. 15% 범위에서만 보정하고, 실제로 좁아진 셀·저장 행이 없는 편집 문단·더 큰 폭 차이는 계속 재배치한다. 마지막 줄의 넘침은 필요할 때만 압축한다.

## 확인 방법

첨부 기준 페이지(윤리기준 실제 3쪽)를 동일한 96 dpi 페이지 그리기로 비교한다. 제목의 이동 폭은 기존 405.25 px에서 416 px로 수정했으며, PDF에서 추출한 폭도 416 px다. 첫 본문 문단의 둘째 줄 시작 위치는 페이지 왼쪽 여백에서 약 52 px 안으로 이동한다.

좁은 구두점의 음수 자간, 반각/글꼴 공백 선택, 들여쓰기/내어쓰기, 마지막 줄/강제 줄바꿈의 정렬 억제, 기존 폭과 좁아진 셀의 구분을 GDI 회귀 검사에 추가했다. 기존 문서 내용·저장 및 GUI 편집 검사는 유지한다.

개발 비교 이미지와 레이아웃 JSON은 `build/spacing-v081/`에 둔다. 글꼴 외형·특수 기호·표 가로 위치·테두리 종류 등의 기존 차이를 이번 수정에서 모두 해결한 것은 아니다. 행 추적 보정은 원본 PDF의 글자별 좌표를 입력으로 사용하지 않으며, 모든 문서의 글자 위치가 원본과 일치한다는 의미가 아니다.

최종 검증: CTest 21개 통과. 샘플 3종 총 41쪽을 렌더링하여 17/20/4쪽과 강제 글자 분할 0건을 확인했다. 요청 페이지의 본문 영역에서 기준 JPG와의 평균 회색조 차이는 37.05에서 24.44로 감소했다(0~255 척도, 동일 크기로 맞춘 픽셀 비교이며 글자별 정확도 점수는 아님).
