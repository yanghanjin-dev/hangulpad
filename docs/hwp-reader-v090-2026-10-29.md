# 0.9.0 HWP 5.x 읽기

2026-10-29. HWP 5.x 문서를 읽는다. 엔진 API는 `include/hp/hwp.h`.

## 구조

```
.hwp ─ cfb.c ─ FileHeader / DocInfo / BodyText·ViewText / BinData / 요약 정보
         │
       hwp.c ─ 압축 해제(raw deflate) → 레코드(태그·수준·크기) → 수준으로 트리 구성
         │       DocInfo  → Contents/header.xml (글꼴·charPr·paraPr·borderFill)
         │       Section  → Contents/section<n>.xml (p/run/t, tbl, pic, container, rect, equation, secPr …)
         │       BinData  → BinData/image<id>.<ext>, content.hpf (manifest·spine·제목)
         ▼
   hp_hwpx_read_package()  ← .hwpx도 같은 함수를 지남
```

- HWP와 HWPX는 같은 문서 모델의 두 저장 형식이다(한컴이 레코드와 요소를 1:1로 대응시킴). 그래서 IR을 두 번 만들지 않고 HWP 레코드를 OWPML 부품으로 바꿔 기존 리더에 넘긴다. 0.4~0.8에서 쌓은 배치 규칙(저장된 줄 배치, 인라인 표 앞 글자, 떠 있는 표 앵커, 쪽 번호 등)이 HWP에도 그대로 적용된다.
- 변환된 부품은 `doc->package`에 남으므로 `hp_hwpx_write`가 그대로 HWPX로 저장한다(HWP → HWPX 변환). 원본 HWP는 건드리지 않는다.
- 레코드 배치와 값 변환은 한컴 공개 문서 "한글 문서 파일 구조 5.0"을 따르고, 문서가 모호한 부분은 한컴 저장 HWP/HWPX 쌍으로 확인했다. 참고로 확인한 공개 구현: hwplib·hwp2hwpx(Apache-2.0), pyhwp(AGPL, 코드 미사용).

### 주요 변환 규칙 (한컴 저장본 대조로 확인)

| 항목 | HWP | HWPX |
|---|---|---|
| 문단 여백·들여쓰기·간격 | 2배 값 저장, 홀수면 글자 단위 | HwpUnitChar case: 값/2(홀수는 (값−1)/2, unit=CHAR), default: 원값 |
| 줄 간격 | 5.0.2.5 이상은 두 번째 줄 간격 값 | PERCENT 외 종류는 case에서 /2 |
| 테두리/배경 번호 | 1부터, 글자·문단 모양이 0을 참조하면 기본 항목을 1번에 넣고 하나씩 밀림 | 같은 규칙 |
| 테두리 선 종류 2/3 | 바이트 2=DOT, 3=DASH | |
| 색 | COLORREF 0x00BBGGRR, 0xFFFFFFFF=none | #RRGGBB |
| 탭 | 인라인 제어 문자 부가 12바이트: 폭(4) 채움(1) 종류(1) | `<hp:tab width leader type>` |
| 문단 끝 앞이 제어 문자 | | 같은 run에 빈 `<hp:t/>` |
| 확장 제어 문자 | k번째 확장 문자 ↔ k번째 CTRL_HEADER | 해당 위치에 tbl/pic/ctrl |
| 그림 | 개체 공통 속성 + SHAPE_COMPONENT(최상위는 id 두 번) + PICTURE(효과 다음에 원본 크기) | imgClip·imgDim·img binaryItemIDRef="image<id>" |
| 묶음 안 개체 | 공통 속성 없음 | sz 없이 orgSz |

### 보안
- 모든 읽기에 경계 검사. 섹터 체인 순환·범위 밖 섹터·짧은 체인, 레코드 크기, 압축 해제 크기(512 MB), 개체 중첩 깊이(48)를 제한.
- 암호(FileHeader 속성 bit 1)·DRM(bit 4) 문서는 `HP_ERR_UNSUPPORTED`.
- 배포용 문서(bit 2): ViewText/Section<n>의 첫 레코드 DISTRIBUTE_DOC_DATA 256바이트를 MSVC rand() 수열로 풀어 AES-128 키를 얻고(`src/aes128.c`, FIPS-197 시험 벡터 통과) 나머지를 ECB로 복호화. **읽기 전용**: `hp_hwpx_write`·`hp_editor_open`이 거부하고, GUI는 편집·저장 메뉴에서 안내한다.

### 셀의 저장된 줄 배치 검사 (hwpx_read.c, 두 형식 공통)
한컴 HWPX의 셀 문단 줄은 끝 위치가 "셀 안쪽 폭 − 문단 좌우 여백"과 같다. 원본 HWPX 3종(셀 문단 줄 1,540개)에서 예외 0. 사용자 PC에서 한컴오피스가 이 HWPX들을 HWP로 저장한 파일은 셀 줄이 자리표시용(폭 42520 = 본문 기본 150 mm, 모든 줄 세로 위치 0)이어서 그대로 쓰면 글자가 겹친다. 끝 위치가 기대값과 2%(최소 300) 넘게 다르거나 세로 위치가 증가하지 않는 줄은 버리고 다시 배치한다. 안쪽 폭 3000 미만의 아주 작은 셀은 제외.

## 한계와 다음 과제
1. HWP 쓰기 없음. HWP에서 변환한 HWPX는 스타일·탭·번호/글머리표·메모 정의 등을 생략하므로 **한컴오피스에서 열리는지 아직 확인하지 않음**.
2. ~~셀 줄을 다시 배치하면 셀 높이가 달라 쪽이 늘어남(규제합리화 HWP 33쪽)~~ → 0.10.1에서 해결: 줄 높이를 한글 방식(글자 크기 × 줄 간격)으로 계산하고 빈 셀 문단은 문단 끝 글자 크기 사용, 원본과 다른 쪽에서는 저장 위치를 쓰지 않음. 3종 모두 HWPX와 같은 쪽 수.
3. 배포용 문서 시험 파일이 저장소에 없음(pyhwp 시험 파일은 AGPL이라 넣지 않음). 한컴오피스 "배포용 문서로 저장"으로 만든 파일 추가 필요.
4. 그림 효과·글맵시·OLE·양식 개체·덧말·글자 겹침의 표시, HWP 3.x 문서.
