# 0.8.0 본문 편집 및 저장

## 구현

- Windows Unicode 다중 행 입력창과 문단 목록. 본문·표 셀·중첩 표의 텍스트를 선택해서 편집한다.
- 새 문서, 문단 추가·삭제, 현재 문단의 텍스트 실행 취소, 클립보드, 저장·다른 이름으로 저장.
- 미저장 표시 및 문서 전환·종료 시 저장 확인. F2 편집 / F5 현재 내용 페이지 미리보기.
- hp_editor API는 원본 패키지와 XML DOM을 보유하고 문단별 변경을 기록한다. 저장할 때 원본 텍스트와 편집본의 공통 앞뒤 구간을 구해 바뀐 run의 텍스트 범위만 교체한다. 변경하지 않은 run과 그림·표 구조·구역 제어·다른 ZIP 부품은 유지한다.
- 새 문단은 기준 문단의 스타일 참조를 상속한다. 수정한 문단의 기존 linesegarray는 제거한다. 구역·개체 제어를 포함한 문단 삭제와 영역의 마지막 문단 삭제는 거부한다.
- 원본 패키지와 편집 기록은 저장 실패 시에도 메모리에 유지한다. 저장은 기존 libzip 트랜잭션 경로를 사용한다. 임의 IR 변경에 대한 기존 저장 거부는 유지한다.

## 검증

CTest 항목 21개. 새 검사는 아래를 포함한다.

- 한글·이모지·XML 예약문자·줄바꿈·탭·빈 문단, 문단 추가·삭제 및 반복 저장.
- 여러 run에 걸친 수정, 기존 텍스트 요소 속성 및 변경하지 않은 run 보존, 빈 self-closing 문단 편집.
- 본문·표 텍스트를 수정하고 다시 읽어 문단 수와 텍스트를 비교. 미수정 저장에서는 모든 패키지 부품을 바이트 비교하고, 수정 저장에서는 section XML 외의 모든 부품을 바이트 비교.
- 실제 샘플 수정/재열기: 윤리기준 605문단, 규제합리화 468문단, 식약처 41문단의 비어 있지 않은 텍스트에 수정 문자열 추가 후 비교.
- 별도 GUI 통합 테스트에서 실제 네이티브 입력창과 앱 명령을 사용해 새 문서→입력→문단 추가→저장→수정→미리보기→다시 저장→문단 삭제→재열기를 확인한다.
- 기존 GUI 레이아웃·페이지 번호·XML·저장 실패 보호·golden 회귀 검사 유지.

검증 빌드: 동기화 폴더 안에서 연속 덮어쓰기 시 간헐적인 I/O 오류가 발생하여, 최종 빌드와 테스트는 동기화 밖의 작업 디렉터리에서 수행한다. 기본 개발 시에도 README의 BuildRoot 지침을 따른다.

## 범위와 한계

문단별 텍스트 편집 UI이며 페이지 위 직접 입력하는 WYSIWYG는 아니다. 글꼴·크기·정렬 변경, 표/그림/구역의 구조 편집은 제공하지 않는다. 실행 취소는 현재 문단의 입력에 적용되며 문단 추가·삭제 및 문단 전환 전의 입력은 되돌리지 않는다. 지원하지 않는 텍스트 내부 제어 요소가 있으면 편집 반영을 거부한다.

수정된 문단은 다시 배치되므로 원본과 같은 페이지 수나 줄바꿈을 보장하지 않는다. ZIP 내부의 Preview 이미지·텍스트는 갱신하지 않는다. 이번 검증은 자체 엔진에서 저장 파일을 재열고 구조를 비교한 것이며, 한컴오피스에서 수정 파일을 다시 여는 호환성 검증은 수행하지 않았다.
